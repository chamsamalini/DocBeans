# DocBeans Constitution

## Core Principles

### 1. Document-first simplicity
Every workflow starts from the document the user needs. Quick Document asks only relevant questions; Advanced Brief is reserved for work that needs formal requirements, approved knowledge, or traceability.

### 2. Human accountability
All generated content is a draft. DocBeans must preserve supplied facts, avoid invented claims, expose missing information, and require human review before external use.

### 3. Transparent AI choice and cost
The selected provider, model, billing mode, returned token usage, estimated provider cost, DocBeans credits, and DocBeans generation charge must remain understandable. The access fee is separate from AI usage. BYOK must not consume a managed-AI credit.

### 4. Privacy by design
BYOK credentials are session-only, excluded from logs, and never placed in generated documents. Users must be warned before sharing sensitive, medical, legal, or confidential information.

### 5. Consistent professional experience
The DocBeans interface uses the shared Montserrat typography and TalentLens-inspired navy, teal, and coral design tokens. User-selected fonts and themes affect generated documents only. Shared branding, navigation, and policy links must remain consistent across routes.

## Quality Gates

- Production builds must complete successfully before publication.
- Pricing, policy, features, and generation accounting must describe the same billing behavior.
- No inactive control may imply that checkout, installation, or automatic publishing is available.
- Generated job descriptions must expose quality checks and missing publication details.
- All changes to the hosted product must update the relevant specification and be privately deployed only after verification.

## Governance

This constitution is the source of truth for DocBeans product decisions. Feature specifications may add stricter requirements but may not weaken these principles without an explicit revision.
