# Agentic AI Literacy and Building Copilot Agents

## Slide-by-slide rewrite

Audience: executive leaders participating in a facilitated, hands-on session

Scenario: build and test a Procurement Policy Guide agent

Recommended duration: 75–90 minutes

| Slide | Purpose | Revised content | Visual or facilitation treatment |
|---|---|---|---|
| 1. Agentic AI Literacy and Building Copilot Agents | Establish the session outcome | Subtitle: “Choose the right Microsoft agent path and build a grounded policy agent.” | Minimal title slide with one visual motif and no source footer. |
| 2. Learning outcomes | Set measurable expectations | Learners can classify model labels by dimension, choose Agent Builder or Copilot Studio, build a grounded agent, test its answers and identify governance decisions. | Five numbered outcomes. |
| 3. Model labels describe different dimensions | Correct the mixed taxonomy | Separate architecture (GPT, MoE), size (SLM), modality (VLM) and intended capability (LRM, LAM). Treat HLM and LCM as source-specific labels whose definitions require confirmation. | Editable four-axis taxonomy with a visible caveat for HLM and LCM. |
| 4. A model becomes useful through agent design | Distinguish models from agents | A model supplies language capability. An agent adds purpose, instructions, approved knowledge, permissions, tools, testing and distribution. | Editable layered agent stack. |
| 5. Agent Builder and Copilot Studio serve different needs | Support platform selection | Compare intended use, knowledge, actions, publishing, governance and licensing. Avoid describing SharePoint as Agent Builder’s only knowledge source or a demo website as Studio’s only publishing path. | Editable decision matrix with a “choose this when” row. |
| 6. Procurement Policy Guide scenario | Ground the practical work | State the user need, source document, expected users, sample questions and success criteria. | Scenario map linking employee question, approved policy, grounded answer and escalation. |
| 7. Agent Builder workflow | Demonstrate the simple path | Sign in, create the agent, define purpose, add approved knowledge, test, create and share according to tenant policy. Include what the learner should see after each key step. | Six-step editable process. |
| 8. Copilot Studio workflow | Demonstrate the advanced path | Describe the agent, review generated instructions, add knowledge and tools, test, publish and select approved channels. Note the 1,024-character description limit and environment-dependent natural-language creation. | Six-step editable process with a prerequisite callout. |
| 9. Guided practice: test, change and retest | Build the core skill | Time: 12 minutes. Deliverable: before-and-after response pair. Success: the revised answer follows the new instruction and stays grounded. Debrief: identify the instruction that caused the change. | Test loop diagram plus a compact activity brief. |
| 10. Independent task: policy agent | Apply the learning | Time: 20 minutes. Deliverable: shared agent, three test questions and one documented gap. Success: a colleague can access it and answers match the approved document. Debrief: identify one access or permission constraint. | Checklist with time, deliverable, success and debrief fields. |
| 11. Governance before rollout | Add executive relevance | Confirm licensing, knowledge permissions, owner, test evidence, sharing scope, review cycle, escalation and retirement criteria. | Governance gate from private test to controlled rollout. |
| 12. Knowledge check | Assess without revealing answers | Five questions covering taxonomy, source permissions, platform selection, description limits and trial publishing. | Questions only; answers appear on the next slide. |
| 13. Answer key and review guidance | Support facilitation | Provide concise answers plus the misconception each answer corrects. | Two-column answer key. |
| 14. Executive Q & A | Satisfy the requested Q&A requirement | Use two short Q&A pairs on this slide and two on a continuation slide if needed. Cover developer need, platform choice, model selection, sharing and governance. | Question-and-answer pairs with strong separation and no paragraph wall. |
| 15. Governed next steps | Convert learning into action | Confirm licences and document access, nominate one owner, pilot one agent, collect test evidence and agree the review date. | 30-day action path with owner and evidence fields. |

## Generator acceptance rules represented by this rewrite

- Every factual slide identifies its exact supporting filename or URL in speaker notes.
- The knowledge check and answer key remain separate.
- Guided and independent activities include timing, deliverable, success criteria and debrief.
- At least three knowledge-derived visuals are used, with at least two visual forms.
- No ordinary content slide exceeds five bullets, 90 words or 24 words per bullet.
- No Q&A slide contains more than two question-and-answer pairs.
- PPTX package references are checked against the files actually present before download.
